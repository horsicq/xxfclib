The FEAD image is always treated as data. Its bundled FCI/NOS DLLs are never loaded or executed. The inverse functions in xx_fead_restore.c and xx_fead_zlib_encoder.c were independently derived from static instructions and observed sideband metadata; they are MIT licensed. The private cancellable BCJ2 loop in xx_fead_bcj2.c is adapted from xxfclib's existing MIT implementation and polls every 64 KiB.

The BILZ filter in the Adobe Reader 7.0 FEAD producer rebuilds zlib streams with deflateInit2_, an initial recorded flush, and Z_FINISH. The image contains the version string 1.2.1. Original packed encoder settings and optional ten-byte footer patches are retained. Using a different token encoder can change the original file bytes even when it decodes to the same data.

The encoder source is pinned to the author's zlib 1.2.1 archive from https://zlib.net/fossils/zlib-1.2.1.tar.gz . Its SHA256 is 94ded52040ee9dd1c70cc3b9f01da283803c28c1194a5a40659e8cf7545990e3. The complete unmodified source archive is retained beside this file for provenance and source availability. Original zlib copyright and permissive license remain in encoder/zlib.h and the source notices; a verbatim license is in ZLIB_LICENSE.txt.

Only encoder/deflate.c, trees.c, adler32.c, crc32.c and compress.c are compiled. No inflate, gzip-file, ZIP, installer, FCI or dynamic-loading entry points are included. The modified source copies are plainly marked at their first line. Port changes:

- Every compiled externally visible zlib symbol is prefixed fead_z_.
- Memory copy/compare/zero use xx_mem functions unconditionally. Two struct copies in deflateCopy also use xx_mem_copy to prevent compiler-generated CRT imports.
- Historical platform names MSDOS/WINDOWS were changed to compiler platform names so xxfclib's format-selection macros cannot select a 16-bit allocator model.
- Debug-only stdio diagnostics use a private, disabled FEAD_ZLIB_DEBUG conditional.
- zutil.c is omitted. The independently authored wrapper supplies the error strings and unavailable default allocator stubs. Every active encoder instance supplies the shared, bounded xx_mem allocator.

Actual encoder workspace allocations, headers included, are charged to the same memory_used counter as the caller's decoded input, reconstructed CAB workspace and retained emitted file bytes. The encoder is additionally capped at 1 MiB per active state. It checks cancellation for each 64 KiB input slice, preserving original output: 96 controls compare the sliced encoder against unmodified 1.2.1 whole-input compression across sizes, parameters and flush modes. It does not create temporary files or launch processes.

The native reader defaults to a 512 MiB aggregate live-memory ceiling; a caller's smaller memory limit applies before metadata parsing. Combined packed main streams are limited to 128 MiB, reconstructed main data to 256 MiB, the compressed metadata tail and each decoded metadata stream individually to 16 MiB, and each LZMA dictionary to 64 MiB. The shared live-memory accounting includes metadata, decoded streams, inverse workspace, encoder allocations and retained member copies, including realloc peaks. TEST uses RAM without output or temporary files. Outer member names currently support the observed ASCII encodings; CAB names support ASCII and explicitly flagged UTF-8, with unsafe paths rejected.

The CAB optimiser's original versioned FCI compressor is not reproduced. Instead, the reader exposes original inner CAB file payloads beneath the original container's directory name. Carrier prefix and overlay bytes are explicit __carrier_prefix.bin and __carrier_overlay.bin members. It never presents a fabricated CAB or EXE as the original. The current observed CAB grammar requires one carrier skip, no extra lists and a raw folder body with the recorded media filters. Other optimizer grammars, including the observed Adobe 7.0.8 variant, are rejected pending further implementation.

Detailed reports in the source checkout's tests/fead directory include native-inverse-report.json (411 inverse/encoder controls), bcj2-regression-report.json (20 decoder/cancellation controls), encoder-imports.json (compiled symbol/CRT audit) and native-regression-report.json. The final integrated native public-API regression passed 2,296 checks across 63 fixtures with 327 exact payload comparisons; 16 CLI controls also passed with six known synthetic payloads. Separate vendor-cli-regression.json records 12 automatic/explicit list, TEST and extraction cases across the application and standalone builds, with 1,288 exact comparisons against restored fixture payloads. Unsupported Adobe 7.0.8 reconstruction safely fails in four CLI cases. FORMAT.md and provenance.json record this evidence and accompany the installed source module.

The original Adobe 7.0 image exposes 324 records with cursor preservation and memory-only TEST. Independent original MSI tables validate all 294 original Data1 names and lengths; four signed reconstructed PE files pass Authenticode and 688 complete PNG streams pass all 4,144 retained original CRCs. Unsigned payloads do not have an independent original-byte oracle in that distribution, whose MsiFileHash table is empty. Repeating the native/CLI payload comparisons does not replace that missing independent vendor hash evidence.
